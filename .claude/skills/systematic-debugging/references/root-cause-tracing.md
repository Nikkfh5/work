# Root Cause Tracing

Баги проявляются глубоко в call stack. Инстинкт — чинить где ошибка ВИДНА. Это лечение симптома.

**Принцип:** трассируй назад по call chain до источника, чини ТАМ.

## Процесс

```
Симптом → Непосредственная причина → Кто вызвал? → Кто передал плохое значение? → ИСТОЧНИК
```

### Пример для проекта

```
Симптом: json_guard возвращает None для валидного JSON
→ extract_json не находит маркеры <<<JSON>>>
→ worker stdout содержит мусор перед маркерами
→ claude_runner не фильтрует stderr из stdout
→ ROOT CAUSE: subprocess.run не разделяет stdout/stderr
→ FIX: в claude_runner, НЕ в json_guard
```

## Инструментация (когда не видно причину)

```python
import traceback
logger.error("DEBUG task_id=%s value=%r caller=%s",
             task_id, value, traceback.format_stack()[-2].strip())
```

Запусти → собери данные → ПОТОМ анализируй.

## Defense in Depth (после фикса)

Добавь валидацию на каждом слое:
1. Валидация на входе (ранний reject)
2. Guard/assert в середине
3. Проверка на выходе (контракт)

## Частые рационализации

| Отмазка | Реальность |
|---------|-----------|
| "Баг простой" | Простые баги тоже имеют root cause |
| "Нет времени" | Систематический дебаг быстрее гадания |
| "Сначала фикс, потом разберусь" | Первый фикс задаёт паттерн |
| "Тест напишу после" | Тест после фикса не доказывает ничего |
| "Несколько фиксов сразу" | Нельзя изолировать что сработало |
